# Saved outfits and flexible outfit pieces

## Problem

Saved outfits live inside studio; one selection per category prevents layered looks. Source: IDEA-002 developer request.

## Outcome

Find saved looks directly and compose/export outfits with multiple independent pieces of seven types.

## Authority and Roadmap

Explicit developer implementation request on 2026-11-24; IDEA-002 BUILD. Current scoped outcome, no wider roadmap priority invented. DEC-001 team workflow applies.

## Scope

Dedicated saved view, categories, item-based selection/layout, compatible SQL migration and tests. Excludes duplicate instances of one piece, inventory quantities, new AI models, cloud layouts and production deployment.

## Acceptance Criteria

1. AC1: Saved outfits is directly reachable through navigation, with actionable empty state and opening into the studio.
2. AC2: All seven categories are available for creating, editing and filtering; existing jackets display as Outerwear and shoes remain available.
3. AC3: Multiple distinct pieces of one category stay selected and visible, with independent transformation and removal.
4. AC4: Save/reopen retains all selected pieces and individual browser-local layout; PNG export includes all pieces.
5. AC5: Compatible migration preserves existing outfits, ownership isolation and atomic saves.
6. AC6: Empty selection cannot save; load/save errors give feedback and save failures retain composition for retry.
7. AC7: Unsupported accessory processing is explained; standalone accessories and cardigan upper-garment processing remain supported.

## Dependencies

Developer must apply incremental SQL migration to their existing Supabase project before new app database behavior works; supply migration and safe local validation. No external integration needed for implementation.

## UX

[Complete LIGHT specification](../../docs/design/APP-001-saved-outfits.md), delegated Designer refinements within developer-authorized scope.

## Edge Cases

Empty/save/load failures, delete/cancel, missing/deleted pieces, legacy layouts, independent same-category controls and unsupported accessory segmentation. Existing confirmation and feedback patterns retained.

## QA

Per-AC scenarios in design specification. Required: behavioral layout tests, typecheck/build, mocked browser workflows, isolated database old/fresh schema and owner/atomic validation. Production database and local AI image quality are outside this feature verification.

## Technical Constraints

Existing Supabase RLS and security-invoker atomic save retained; private images. Existing `jacket` key retained as Outerwear. Browser-local layouts remain so. DEC-001 applies; no other accepted architecture decision is reversed.
