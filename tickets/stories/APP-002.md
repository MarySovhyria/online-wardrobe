# Browser photo preparation for Vercel

## Problem

Local Python/MLX workers and model environments prevent deploying the current photo workflow unchanged on Vercel; source photos can lose garment fidelity through generation.

## Outcome

Prepare upright standalone clothing on the visitor's device with optional background removal and lighting, then explicitly accept and privately save the result.

## Authority and Roadmap

IDEA-003 BUILD, approved detailed plan and direct “Implement the approved plan.” Current bounded outcome, DEC-002 direction; no deployment authorized.

## Scope

Browser foreground model, worker/assets, lighting/preview/acceptance, retirement of obsolete AI runtime/setup, tests and docs. Excludes worn photos, reconstruction, smoothing/wrinkle repair, paid inference, new database migration and deployment. Ignored model caches/environments remain untouched.

## Acceptance Criteria

1. AC1: Production app processes photos without Python, MLX, child processes or paid inference.
2. AC2: Editor clearly requests upright standalone clothing and removes worn-photo/FLUX controls.
3. AC3: Optional browser background removal gives progress, cancellation, retry and keep-background recovery.
4. AC4: Neutral/Auto/manual lighting is reversible and preserves geometry, transparency and patterns without fabric reconstruction or smoothing.
5. AC5: Only explicitly accepted current preview saves; compare/reset and changing photos/settings cannot save stale output.
6. AC6: Existing clothing, categories, multi-piece outfits, reopen and PNG export remain compatible without a new database migration.
7. AC7: Documentation and build assets support Vercel, including environment/auth setup, first-use downloads, device limits and attribution.

## Dependencies

Pinned ONNX Runtime Web and U2NetP assets with checksum/attribution; build setup owned by runtime implementation. Supabase unchanged. Real browser checks required before closeout.

## UX

[Approved LIGHT specification](../../docs/design/APP-002-photo-preparation.md); planning Product Owner/Designer/QA role results inform scope. New Auto light preference explicitly confirmed.

## Edge Cases

Invalid/decode-failed files, transparent sources, flat masks, model/network/device failure, cancel/retry, setting/photo changes during inference, compare while accepting and metadata-only edits. Keep-background fallback avoids model dependency.

## QA

AC1 build without local workers; AC2 editor choices; AC3 real model and failure/retry/cancel; AC4 pixel/alpha tests; AC5 browser acceptance/saved-byte checks and races; AC6 existing outfit tests/browser flow; AC7 asset/static-output/docs review. Chrome and WebKit smoke tests, typecheck/build/test/format required. Real production Supabase and deployment outside scope.

## Technical Constraints

No paid inference/separate backend. Single-thread WASM in dedicated worker, pinned same-origin model/assets, original-based non-generative lighting. Existing private WebP persistence/schema retained. DEC-001 workflow and DEC-002 developer direction apply.
