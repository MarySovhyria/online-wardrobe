# Mobile preview-centered outfit and photo editing

## Problem

Mobile users must scroll between outfit preview, selection and adjustments; photo lighting similarly separates controls from visible preview.

## Outcome

Choose and adjust clothing while keeping its preview visible, with no page-long selection scroll.

## Authority and Roadmap

IDEA-004 BUILD and direct developer request. Current bounded outcome; DEC-001 workflow/DEC-002 photo semantics retained. No deployment.

## Scope

Mobile picker/workspace/transform controls plus sticky existing photo-lighting preview. Preserve desktop and existing persistence. Exclude new outfit brightness/filter semantics, schema/model changes and deployment.

## Acceptance Criteria

1. AC1: All seven mobile category buttons are reachable beside the board without scrolling a page-long clothing list.
2. AC2: Each category opens a labelled, bounded clothing picker with selected states, close/Done, useful empty state and internal scrolling.
3. AC3: Multiple pieces/category toggle independently with immediate board updates and retained composition.
4. AC4: Active-piece rotation/size/actions and visible board share the mobile editing viewport; existing photo-lighting preview remains visible while its controls are used.
5. AC5: Sheet does not cover the reduced board; opening/closing preserves page position and creates no horizontal overflow at tested mobile sizes.
6. AC6: Keyboard/modal focus, dismissal, focus restoration, touch targets and responsive desktop transition work.
7. AC7: Desktop studio, multi-piece saves, existing layouts, reopen and PNG export remain compatible without schema changes.

## Dependencies

Existing wardrobe items/selection/layout and browser native dialog; no backend changes or new dependencies. Mobile tools implemented in isolated component; parent integrates responsive board/photo preview.

## UX

[Complete FULL specification](../../docs/design/APP-003-mobile-studio.md), delegated PO then Designer, within direct request. Optional brightness question remained unanswered; stated default interpretation applies; no per-outfit brightness feature invented.

## Edge Cases

Empty selection/category, repeated categories, active removal, occluded items, sheet scroll, backdrop/Escape/Done, switching category, resize to desktop and short portrait height. Existing save/error handling retained.

## QA

AC1–6 real browser 390×844 and375×667 geometry/interactions/focus/modal dismissal/desktop transition; existing photo preparation brightness preview and save acceptance; AC7 existing layout tests, mocked save/reopen/export browser and desktop flow. Typecheck/build/test/format. No production data/deployment.

## Technical Constraints

Existing <=760px breakpoint, same board aspect ratio/normalized pose and WebP pipeline, browser-local layouts and Supabase selection unchanged. DEC-001/DEC-002 inspected; no new durable architecture decision.
